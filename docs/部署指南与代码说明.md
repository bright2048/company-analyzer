## 系统概述

本系统是一个企业调研报告自动化生成平台，主要功能包括：

- **用户认证**：手机号验证码登录/注册，支持实名认证
- **报告生成**：输入公司名称，AI自动搜索信息并生成专业分析报告
- **园区匹配**：分析企业与园区的匹配度、上下游关系、扩租需求
- **报告导出**：支持Word和PDF格式下载
- **园区管理**：支持Excel批量导入园区企业名单

## 技术栈

| 层级 | 技术 | 说明 |
|:----:|------|------|
| 前端 | React 19 + TypeScript | 用户界面 |
| 样式 | Tailwind CSS 4 + shadcn/ui | UI组件库 |
| 后端 | Express 4 + tRPC 11 | API服务 |
| 数据库 | MySQL 8.0 / TiDB | 数据存储 |
| ORM | Drizzle ORM | 数据库操作 |
| 存储 | S3兼容存储（MinIO/OSS） | 文件存储 |
| AI | 通义千问/OpenAI兼容API | 报告生成 |
| 短信 | 腾讯云SMS | 验证码发送 |
| 实名 | 腾讯云FaceID | 身份认证 |

## 部署步骤

### 步骤1：安装Node.js

```bash
# 使用nvm安装Node.js
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.0/install.sh | bash
source ~/.bashrc
nvm install 20
nvm use 20

# 安装pnpm
npm install -g pnpm
```

### 步骤2：克隆代码

```bash
cd /var/www
git clone https://github.com/bright2048/company-analyzer.git
cd company-analyzer
```

### 步骤3：安装依赖

```bash
pnpm install
```

### 步骤4：配置环境变量

```bash
# 复制示例配置文件
cp .env.example .env

# 编辑配置文件
nano .env
```

详细配置见[环境变量配置](#环境变量配置)章节。

### 步骤5：初始化数据库

```bash
# 推送数据库表结构
pnpm db:push
```

### 步骤6：构建生产版本

```bash
pnpm build
```

### 步骤7：启动服务

**方式1：直接启动（测试用）**
```bash
pnpm start
```

**方式2：使用PM2（生产推荐）**
```bash
# 安装PM2
npm install -g pm2

# 启动服务
pm2 start dist/index.js --name company-analyzer

# 设置开机自启
pm2 startup
pm2 save
```

### 步骤8：配置Nginx反向代理（可选）


### 核心文件说明

#### 前端文件

| 文件路径 | 作用 | 大白话解释 |
|---------|------|-----------|
| `client/src/App.tsx` | 应用入口和路由配置 | 就像一本书的目录，告诉系统访问不同网址时显示哪个页面 |
| `client/src/pages/Home.tsx` | 首页 | 用户看到的第一个页面，有搜索框可以输入公司名 |
| `client/src/pages/Login.tsx` | 登录页 | 用户输入手机号和验证码登录的页面 |
| `client/src/pages/Verify.tsx` | 实名认证页 | 新用户填写姓名和身份证号进行认证的页面 |
| `client/src/pages/ReportDetail.tsx` | 报告详情页 | 显示生成的报告内容，可以下载Word/PDF |
| `client/src/pages/ReportHistory.tsx` | 历史报告页 | 显示之前生成过的所有报告列表 |
| `client/src/pages/ParkCompanies.tsx` | 园区企业页 | 管理园区内的企业名单，支持Excel导入 |
| `client/src/pages/Settings.tsx` | 设置页 | 配置数据源（网络搜索/天眼查/企查查） |
| `client/src/lib/trpc.ts` | tRPC客户端 | 前端调用后端API的"电话线"，让前端能和后端通信 |
| `client/src/_core/hooks/useAuth.ts` | 认证Hook | 提供登录状态，让页面知道用户是否已登录 |

#### 后端文件

| 文件路径 | 作用 | 大白话解释 |
|---------|------|-----------|
| `server/routers.ts` | API路由定义 | 后端的"接线员"，定义了所有API接口，前端发请求到这里 |
| `server/db.ts` | 数据库操作 | 和数据库打交道的"翻译官"，把数据存进去或取出来 |
| `server/sms.ts` | 短信服务 | 负责发送验证码短信，调用腾讯云短信API |
| `server/faceId.ts` | 实名认证服务 | 负责身份验证，调用腾讯云人脸核身API |
| `server/reportExport.ts` | 报告导出 | 把报告内容转换成Word或PDF文件 |
| `server/storage.ts` | 文件存储 | 把生成的报告文件存到S3/MinIO |
| `server/_core/llm.ts` | LLM调用 | 调用AI大模型生成报告内容 |
| `server/_core/env.ts` | 环境变量 | 读取.env配置文件中的各种密钥和设置 |
| `server/_core/context.ts` | 请求上下文 | 每个请求的"身份证"，记录当前用户是谁 |

#### 数据库文件

| 文件路径 | 作用 | 大白话解释 |
|---------|------|-----------|
| `drizzle/schema.ts` | 数据库表结构 | 定义数据库里有哪些表、每个表有哪些字段，就像Excel表格的表头 |

## 代码协作逻辑

### 用户登录流程

```
用户输入手机号 → 点击"获取验证码"
    ↓
前端(Login.tsx) → 调用 trpc.auth.sendSmsCode
    ↓
后端(routers.ts) → 生成验证码 → 调用 sms.ts 发送短信
    ↓
后端(db.ts) → 保存验证码到数据库
    ↓
用户收到短信 → 输入验证码 → 点击"登录"
    ↓
前端(Login.tsx) → 调用 trpc.auth.loginByPhone
    ↓
后端(routers.ts) → 验证验证码 → 查找/创建用户 → 生成JWT
    ↓
后端 → 设置Cookie → 返回登录成功
    ↓
前端 → 跳转到首页或实名认证页
```

### 报告生成流程

```
用户输入公司名 → 点击"生成报告"
    ↓
前端(Home.tsx) → 检查是否登录 → 调用 trpc.report.create
    ↓
后端(routers.ts) → 创建报告记录（状态：pending）
    ↓
后端 → 异步执行报告生成任务
    ↓
后端(llm.ts) → 调用AI搜索公司信息
    ↓
后端(llm.ts) → 调用AI生成报告各章节
    ↓
后端(db.ts) → 更新报告内容到数据库
    ↓
后端 → 获取园区企业列表 → 分析匹配度
    ↓
后端(db.ts) → 保存匹配分析结果
    ↓
后端 → 更新报告状态为completed
    ↓
前端(ReportDetail.tsx) → 轮询报告状态 → 显示报告内容
```

### 报告导出流程

```
用户点击"下载Word"或"下载PDF"
    ↓
前端(ReportDetail.tsx) → 调用 trpc.report.export
    ↓
后端(routers.ts) → 获取报告内容
    ↓
后端(reportExport.ts) → 生成Word/PDF文件
    ↓
后端(storage.ts) → 上传到S3/MinIO
    ↓
后端 → 返回下载URL
    ↓
前端 → 打开下载链接
```

## 腾讯云服务配置

### 短信服务配置

1. 登录[腾讯云短信控制台](https://console.cloud.tencent.com/smsv2)
2. 创建应用，获取 SDK AppID
3. 创建签名（需要审核）
4. 创建短信模板，模板内容示例：
   ```
   您的验证码是{1}，{2}分钟内有效。如非本人操作，请忽略。
   ```
5. 获取 SecretId 和 SecretKey（访问管理 → 访问密钥）

### 实名认证配置

1. 登录[腾讯云人脸核身控制台](https://console.cloud.tencent.com/faceid)
2. 开通服务
3. 创建规则，获取 RuleId
4. 使用相同的 SecretId 和 SecretKey

## 常见问题

### Q: 报告生成失败，提示LLM调用错误？

检查以下配置：
1. `BUILT_IN_FORGE_API_URL` 不要包含 `/v1`
2. `BUILT_IN_FORGE_API_KEY` 是否正确
3. `LLM_MODEL` 是否是有效的模型名称

### Q: 短信发送失败？

检查以下配置：
1. 腾讯云账户是否有余额
2. 短信签名和模板是否已审核通过
3. SecretId 和 SecretKey 是否正确

### Q: 文件上传失败？

检查以下配置：
1. S3/MinIO 服务是否正常运行
2. Bucket 是否已创建
3. Access Key 和 Secret Key 是否正确
4. 如果使用 MinIO，确保 `S3_FORCE_PATH_STYLE="true"`

### Q: 数据库连接失败？

检查以下配置：
1. `DATABASE_URL` 格式是否正确
2. 数据库服务是否正常运行
3. 用户名密码是否正确
4. 防火墙是否允许连接
