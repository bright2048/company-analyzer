# 数智深圳湾智能体 (KunLing CIS) 源代码说明文档

本文档用大白话解释系统的各个源代码文件的作用，以及它们之间是如何配合工作的。

---

## 一、系统整体架构

数智深圳湾智能体是一个**前后端分离**的Web应用，采用现代化的技术栈构建。简单来说，系统分为三大部分：

| 部分   | 位置       | 作用                                       |
| ------ | ---------- | ------------------------------------------ |
| 前端   | `client/`  | 用户看到的界面，负责展示数据和接收用户操作 |
| 后端   | `server/`  | 处理业务逻辑，调用AI生成报告，操作数据库   |
| 数据库 | `drizzle/` | 存储企业信息、报告内容、任务状态等数据     |

**通俗理解**：前端就像餐厅的服务员，负责和顾客打交道；后端就像厨房，负责做菜（生成报告）；数据库就像仓库，存放所有的食材和菜谱（数据）。

## 二、前端文件说明 (`client/src/`)

### 2.1 入口文件

| 文件        | 作用                                             |
| ----------- | ------------------------------------------------ |
| `main.tsx`  | 整个前端应用的启动入口，就像汽车的点火开关       |
| `App.tsx`   | 定义页面路由，决定用户访问不同网址时显示哪个页面 |
| `index.css` | 全局样式设置，定义颜色、字体等视觉风格           |

### 2.2 页面文件 (`client/src/pages/`)

每个页面文件对应用户看到的一个完整页面：

| 文件                | 对应页面   | 功能说明                                 |
| ------------------- | ---------- | ---------------------------------------- |
| `Home.tsx`          | 首页       | 显示搜索框，用户输入公司名称开始查询     |
| `BatchQuery.tsx`    | 批量查询页 | 上传CSV文件，一次查询多个企业            |
| `ReportDetail.tsx`  | 报告详情页 | 展示生成的企业分析报告，支持导出Word/PDF |
| `ReportHistory.tsx` | 历史报告页 | 查看之前生成的所有报告列表               |
| `ParkCompanies.tsx` | 园区企业页 | 管理园区内的企业名单，支持Excel导入      |
| `Settings.tsx`      | 设置页     | 配置数据源（天眼查/企查查API）           |
| `NotFound.tsx`      | 404页面    | 用户访问不存在的页面时显示               |

**页面之间的关系**：

```
首页 → 输入公司名 → 报告详情页（显示生成进度和结果）
     ↓
批量查询页 → 上传CSV → 查看任务进度 → 打包下载
     ↓
历史报告页 → 点击某个报告 → 报告详情页
```

### 2.3 组件文件 (`client/src/components/`)

组件是可以重复使用的界面"零件"，就像乐高积木：

| 文件/目录             | 作用                                              |
| --------------------- | ------------------------------------------------- |
| `ui/`                 | 基础UI组件（按钮、输入框、卡片等），来自shadcn/ui |
| `DashboardLayout.tsx` | 后台管理布局模板，带侧边栏导航                    |
| `ErrorBoundary.tsx`   | 错误边界，当页面出错时显示友好提示而不是白屏      |

### 2.4 工具文件

| 文件                        | 作用                                           |
| --------------------------- | ---------------------------------------------- |
| `lib/trpc.ts`               | 前端和后端通信的"翻译官"，让前端能调用后端接口 |
| `contexts/ThemeContext.tsx` | 主题切换功能（深色/浅色模式）                  |
| `_core/hooks/useAuth.ts`    | 用户登录状态管理                               |

## 三、后端文件说明 (`server/`)

### 3.1 核心业务文件

| 文件              | 作用                              | 大白话解释                                   |
| ----------------- | --------------------------------- | -------------------------------------------- |
| `routers.ts`      | **最重要的文件**，定义所有API接口 | 就像餐厅的菜单，列出所有可以点的"菜"（功能） |
| `db.ts`           | 数据库操作函数                    | 负责从仓库（数据库）取东西和存东西           |
| `storage.ts`      | 文件存储操作                      | 把生成的Word/PDF文件上传到云存储             |
| `reportExport.ts` | 报告导出功能                      | 把报告内容转换成Word或PDF格式                |

### 3.2 `routers.ts` 详细说明

这个文件是后端的"大脑"，定义了所有功能接口：

```
routers.ts
├── auth（认证相关）
│   ├── me - 获取当前登录用户信息
│   └── logout - 退出登录
│
├── parkCompany（园区企业管理）
│   ├── list - 获取企业列表
│   ├── create - 添加新企业
│   ├── update - 修改企业信息
│   ├── delete - 删除企业
│   └── importFromXls - 从Excel导入企业
│
├── report（报告管理）
│   ├── list - 获取报告列表
│   ├── create - 创建新报告
│   ├── generate - 生成报告内容（调用AI）
│   ├── exportWord - 导出Word文档
│   └── exportPdf - 导出PDF文档
│
├── batchTask（批量任务）
│   ├── list - 获取任务列表
│   ├── create - 创建批量任务（上传CSV）
│   └── downloadAll - 打包下载所有报告
│
└── dataSource（数据源配置）
    ├── list - 获取配置列表
    └── setActive - 设置当前使用的数据源
```

### 3.3 核心框架文件 (`server/_core/`)

这些是系统的"基础设施"，一般不需要修改：

| 文件         | 作用                                   |
| ------------ | -------------------------------------- |
| `index.ts`   | 服务器启动入口                         |
| `trpc.ts`    | tRPC框架配置，实现类型安全的前后端通信 |
| `llm.ts`     | AI大模型调用封装，用于生成报告         |
| `context.ts` | 请求上下文，包含用户信息等             |

## 五、代码配合逻辑

### 5.1 单个企业查询流程

```
用户操作                    前端                      后端                     数据库
   │                         │                         │                         │
   │ 1.输入公司名            │                         │                         │
   │─────────────────────────>│                         │                         │
   │                         │ 2.调用report.create      │                         │
   │                         │─────────────────────────>│                         │
   │                         │                         │ 3.创建报告记录           │
   │                         │                         │─────────────────────────>│
   │                         │                         │<─────────────────────────│
   │                         │<─────────────────────────│ 返回报告ID              │
   │                         │                         │                         │
   │ 4.跳转到报告详情页       │                         │                         │
   │<─────────────────────────│                         │                         │
   │                         │ 5.调用report.generate    │                         │
   │                         │─────────────────────────>│                         │
   │                         │                         │ 6.调用AI生成报告         │
   │                         │                         │───────>AI               │
   │                         │                         │<───────                 │
   │                         │                         │ 7.保存报告内容           │
   │                         │                         │─────────────────────────>│
   │                         │<─────────────────────────│                         │
   │ 8.显示报告内容           │                         │                         │
   │<─────────────────────────│                         │                         │
```

### 5.2 批量查询流程

```
1. 用户上传CSV文件
   ↓
2. 前端读取文件内容，转成base64编码
   ↓
3. 调用 batchTask.create 接口
   ↓
4. 后端解析CSV，提取企业名称列表
   ↓
5. 检查数量是否超过50个限制
   ↓
6. 创建批量任务记录，为每个企业创建报告记录
   ↓
7. 启动后台异步任务，逐个生成报告
   ↓
8. 前端每5秒刷新一次，显示进度
   ↓
9. 全部完成后，用户点击"打包下载"
   ↓
10. 后端合并所有报告，上传到云存储
   ↓
11. 返回下载链接
```

### 5.3 企业未找到的处理逻辑

```
1. 用户输入一个不存在或不知名的企业名称
   ↓
2. AI收到查询请求
   ↓
3. AI检查自己的知识库，发现不了解这个企业
   ↓
4. AI返回 [NOT_FOUND] 标记
   ↓
5. 后端检测到这个标记
   ↓
6. 将报告状态设为"failed"，错误信息为"未找到该企业"
   ↓
7. 前端显示友好的提示，告诉用户：
   - 请检查企业名称是否正确
   - 系统不会编造虚假信息
```

## 六、关键技术说明

### 6.1 tRPC（类型安全的API调用）

传统方式调用API需要手动定义请求和响应的数据格式，容易出错。tRPC让前端和后端共享类型定义，编译时就能发现错误。

**好处**：前端调用后端接口时，IDE会自动提示有哪些接口、需要什么参数、返回什么数据。

### 6.2 Drizzle ORM（数据库操作）

ORM（对象关系映射）让开发者用JavaScript代码操作数据库，而不用写SQL语句。

**例子**：

```javascript
// 传统SQL写法
SELECT * FROM company_reports WHERE id = 1

// Drizzle写法
db.select().from(companyReports).where(eq(companyReports.id, 1))
```

### 6.3 后台异步任务

报告生成需要调用AI，可能需要几十秒甚至几分钟。如果让用户一直等待，体验很差。

**解决方案**：

1. 用户提交请求后，立即返回"任务已创建"
2. 后台异步处理，不阻塞用户操作
3. 前端定时刷新，显示最新进度

## 七、文件修改指南

如果需要修改系统功能，参考以下指南：

| 需求                 | 需要修改的文件                                                       |
| -------------------- | -------------------------------------------------------------------- |
| 修改页面样式         | `client/src/index.css` 或对应的页面文件                              |
| 添加新页面           | 在 `client/src/pages/` 创建新文件，在 `App.tsx` 添加路由             |
| 添加新API接口        | 在 `server/routers.ts` 添加新的procedure                             |
| 修改数据库表结构     | 修改 `drizzle/schema.ts`，然后运行 `pnpm db:push`                    |
| 修改AI生成的报告格式 | 修改 `server/routers.ts` 中的 `generateCompanyReport` 函数里的prompt |
| 修改品牌名称         | 修改 `client/src/pages/Home.tsx` 和其他页面的header部分              |

## 八、常见问题

**Q: 为什么报告生成需要这么长时间？**
A: 报告生成需要调用AI大模型，AI需要"思考"并生成几千字的专业分析内容，这个过程本身就需要时间。

**Q: 为什么有些企业查不到？**
A: 系统使用AI生成报告，AI只能基于它训练数据中包含的企业信息。对于不知名或新成立的企业，AI可能没有相关信息，此时会明确告知用户，而不是编造虚假内容。

**Q: 批量查询为什么限制50个？**
A: 每个报告生成都需要调用AI，消耗计算资源。限制数量是为了保证系统稳定性和响应速度。
